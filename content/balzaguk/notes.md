## [01] 프로젝트 배경과 장민석의 담당 범위

발자국은 제4회 문화체육관광 인공지능·데이터 활용 공모전에 4인 팀으로 참가해 2026년 6월 17일부터 26일까지 10일 동안 만든 반려견 동반 여행 플래너입니다. 데모 시나리오는 서울에서 출발해 전주로 가는 대형견(골든 리트리버, 더위에 약한 체질) 보호자로 고정했습니다. 처음 기획은 검색과 둘러보기 중심이었으나, 개발 도중 AI와 대화를 주고받으며 여정이 채워지는 대화형 플래너로 방향을 바꿨고, 꾸미기, 커뮤니티, 브이로그 같은 기능은 이때 걷어냈습니다. 장민석은 풀스택으로 참여해 FastAPI 백엔드(헥사고날 구조), Gemini 에이전트, 공공데이터 적재 스크립트와 DB 설계, Docker와 Railway, Vercel 배포를 맡았고, 프론트엔드에서는 서버와 연결되는 화면을 모두 만들었습니다. 메인 페이지는 팀원이 맡았습니다. 기획서와 공모전 신청서는 팀원 공용 가이드 문서를 두고 팀이 함께 작성했습니다.

## [02] 후보를 먼저 주고 AI는 순서만 고르게 한 이유

코스 추천에서 가장 피하고 싶었던 것은 실제로 없는 시설이 화면에 나오는 상황이었습니다. 그래서 DB에서 반려견 크기로 입장 가능한 시설만 추리고, 미용, 용품, 병원, 약국 같은 노이즈 업종과 숙박을 뺀 뒤, 이동 수단별 기준점(KTX는 전주역, 버스는 고속버스터미널, 자차는 후보 평균 중심)에서 가까운 40곳만 id와 함께 프롬프트에 넣었습니다. Gemini는 이 목록에서 id 순서와 한두 문장 설명만 JSON으로 돌려줍니다. 응답은 정규식으로 JSON 블록을 떼어 파싱하고, 후보 id 집합에 없는 값은 버립니다. 파싱이 깨지거나 호출이 예외로 끝나면 가장 가까운 곳부터 잇는 최근접 이웃 정렬로 코스를 채우고, 정류장 수는 하루 4곳, 최대 12곳으로 제한했습니다. 같은 패턴을 대화, 추천, 증상 안내 에이전트에도 적용했습니다. 증상 안내는 응답에 "수의사"가 없으면 면책 문구를 덧붙이고, 긴급도가 low, medium, high가 아니면 medium으로 되돌립니다. 설계 문서에는 도구 호출(tool-calling) 방식이 적혀 있었지만 왕복이 두 번 생겨 느려서 후보를 프롬프트에 직접 넣는 방식으로 바꿨고.

## [03] 경량 모델과의 대화에서 겪은 문제와 대응

기본 모델은 경량 Gemini 모델이었고, 이 모델은 few-shot 예시에 들어 있던 지역명을 사용자 목적지로 그대로 옮겨 적거나, 이미 받은 이동 수단을 다시 묻는 일이 있었습니다. 대응은 네 겹으로 했습니다. 먼저 few-shot 예시에서 특정 여행지를 아예 지웠습니다. 다음으로 매 턴 "지금까지 파악된 정보, 다시 묻지 마세요"라는 블록에 현재 슬롯을 JSON으로 넣었습니다. 온도는 0.7로 두었는데, 더 낮추면 예시를 그대로 베끼는 경향이 강해진다고 판단했기 때문입니다. 세 번째로 LLM이 돌려준 목적지가 사용자 발화 원문에 없으면 코드에서 버리는 그라운딩을 넣었습니다. 마지막으로 코스를 만들지 여부는 도메인 객체의 next_stage 규칙이 판단하게 했습니다. 필수 슬롯은 목적지, 이동 수단, 숙박 세 가지이고, 출발 시각은 묻지 않고 오전 9시로 가정합니다. LLM 호출이 실패하면 빈 응답을 돌려주고 규칙 질문과 선택칩으로 대화를 이어 갑니다. 한계는 목적지 그라운딩이 단순 문자열 포함 검사라서 "전주말고 부산" 같은 표현은 가장 마지막에 나온 지명을 고르는 별도 규칙에 의존한다는 점입니다. 이 흐름의 성공률은 정량으로 재지 않았습니다 (측정 전).

## [04] 공공데이터 정제에서 부딪힌 문제

원천 CSV는 기관마다 인코딩이 달라 utf-8-sig와 cp949를 파일별로 지정해 읽었습니다. 좌표도 위경도가 바로 있는 파일과 평면 좌표(TM)로 된 인허가 데이터가 섞여 있어 pyproj로 WGS84로 바꿨습니다. 이때 시설 적재 스크립트는 EPSG:5174, 동물병원 적재 스크립트는 EPSG:2097을 써서 같은 계열 데이터에 서로 다른 좌표계 코드가 들어갔습니다. 동물병원 쪽은 종로의 병원 한 곳을 실제 위치와 대조해 검증했지만, 두 코드를 한 곳으로 통일하지 못한 것은 남은 과제입니다. 중복은 이름과 좌표가 완전히 같은 행을 합쳤고, 적재 후 점검에서 소수점 5자리 기준으로 11쌍(0.04%)이 남아 무해하다고 보고 보류했습니다. 바다에 찍힌 좌표는 시군구별 좌표 중앙값에서 50km 넘게 떨어진 시설을 적재 전에 제외하는 방식으로 걸렀습니다. 외부 행정경계 데이터 없이 쓸 수 있고 중앙값이 이상치에 강하다는 점을 보고 골랐으며, 시설이 5곳 미만인 시군구는 건너뜁니다. 이 단계에서 몇 건이 제외됐는지는 따로 집계하지 않았습니다 (측정 전). 동물병원은 원본 10,548곳 중 좌표 변환에 성공한 9,299곳을 적재했습니다.

## [04] 3NF 설계와 의도적으로 둔 예외

지역과 분류를 공유 차원 표로 두어 시설, 무장애 시설이 같은 지역과 분류를 참조하게 했습니다. 시설 본체와 반려동물 규정은 1:1로 나눴고, 허용 크기는 별도 표로 분리했습니다. 적재 후 운영 DB를 직접 조회해 시설 30,417행과 규정 30,417행이 정확히 일치하고, 허용 크기 88,678행이 small, medium, large 세 값으로만 구성되며, 지역과 분류 FK NULL, 좌표 NULL, 고아 참조가 모두 0건임을 확인했습니다. 설계를 고친 사례도 있습니다. 처음에는 음식점 업태를 시설 분류 차원에 함께 넣으려 했으나, 업태 38종은 계층형 시설 분류와 성격이 달라 한 표가 두 책임을 지게 된다고 보고 음식점 표의 문자열 컬럼으로 뺐습니다. 반대로 코스 카드 썸네일은 조인 없이 한 번에 읽으려고 대표 이미지 URL을 음식점 본체에 복제했고, 전체 이미지는 별도 표를 정본으로 유지했습니다. 반려동물 동반 식당은 전주 음식점과 반려동물 동반 시설을 식당명으로 정확 매칭하면 2건뿐이어서, 동반 시설 CSV의 음식과 카페, 한국관광공사 동반여행 음식점을 직접 적재해 967건으로 늘렸습니다. 재적재는 전체 삭제 후 5,000행 단위 벌크 삽입 방식이라 증분 갱신은 되지 않습니다.

## [05] 경유지 선별의 구현 세부와 한계

자차를 고른 경우에만 경유지를 계산합니다. 서울과 전주 좌표를 잇는 선분을 기준으로, 위도 평균에서 경도 1도의 거리를 보정한 평면 근사 좌표계로 각 시설을 투영해 진행도 t와 수직 이탈 거리를 구합니다. 후보는 반려동물 동반 문화시설 CSV에서 대형견 입장이 가능하고, 공원, 박물관, 유적, 휴게 같은 업종 힌트가 있거나 실외 시설인 곳만 남기며, 병원, 숙박, 카페, 식당은 제외합니다. 진행도 구간을 초반, 중반, 후반 세 칸으로 나눠 각 구간에서 이탈 거리가 가장 짧은 시설 하나씩 고르기 때문에 한쪽에 몰리지 않습니다. 휴게소는 공공데이터에 반려동물 동반 정보가 없어 고속도로 휴게소 두 곳을 시드로 두고, 선택 결과에 휴게소가 없으면 중간에 끼워 넣습니다. 이 기능은 DB가 아니라 CSV를 한 번 읽어 프로세스 메모리에 캐시하는 방식이고, 서울에서 전주 구간에만 동작합니다. 직선 근사라 실제 고속도로에서 멀리 떨어진 시설이 섞일 수 있으며, 실제 도로 경로와 얼마나 어긋나는지는 비교하지 않았습니다 (측정 전).

## [06] 배포 구성과 첫 요청 지연 대응

Docker 이미지는 node 단계에서 Vite 빌드를 끝낸 뒤 결과물만 python 3.13 slim 단계로 옮기고, FastAPI가 정적 파일과 /api를 같은 출처에서 제공합니다. 프론트의 API 주소를 '/api'로 고정할 수 있어 CORS 설정과 프론트 환경변수가 거의 필요 없어졌고, 빌드 시점에 넣는 값은 지도 클라이언트 ID 하나만 남았습니다. 경유지와 둘레길 계산에 쓰는 CSV는 이미지에 함께 넣었고, DB는 외부 Neon PostgreSQL을 씁니다. 컨테이너가 뜰 때 alembic upgrade head를 먼저 실행합니다. 서버가 요청을 받기 시작하면 백그라운드 작업이 전주, 대형견 조건의 당일치기와 1박 코스를 미리 호출해 캐시를 채우므로 부팅이 막히지 않습니다. 같은 조건의 동시 요청은 키별 asyncio.Lock으로 한 번만 계산합니다. 캐시가 프로세스 메모리에만 있어 재시작하면 비고, 데이터가 바뀌지 않는 데모라는 전제가 필요합니다. 적재 중 마이그레이션 버전과 실제 테이블이 어긋난 적이 있어, 인제스트로 테이블을 만든 뒤 alembic stamp head로 버전만 맞췄습니다. 자동화 테스트는 사용자 모듈 10개뿐이라 에이전트 검증과 폴백 경로는 테스트로 보호되지 않습니다. 첫 요청 지연이 얼마나 줄었는지는 재지 않았습니다 (측정 전). 현재 배포는 내려가 있습니다.
